# 01 · 项目总览与系统架构

## 一、项目定位

`web-api` 是整套 IM 系统的 **后端网关与业务服务层**，基于 PHP 8.1 + Hyperf 3 + Swoole 5 构建的高性能协程框架。它同时服务两类调用方：

| 调用方             | 路由前缀        | 说明                                             |
| ------------------ | --------------- | ------------------------------------------------ |
| C 端 App / Web     | `api/v1/...`    | 用户注册、登录、个人资料、笔记、圈子、聊天分组等 |
| 管理后台（web-ht） | `/ht/v1/...`    | 用户管理、圈子审核、帮办管理、通知、参数配置等   |
| 内部服务调用       | `/internal/...` | 限流配置等内部接口（IP 白名单鉴权）              |

## 三、服务端口与进程模型

| 服务             | 类型             | 端口            | 配置                         |
| ---------------- | ---------------- | --------------- | ---------------------------- |
| HTTP Server      | `SWOOLE_PROCESS` | `APP_PORT=9005` | `config/autoload/server.php` |
| WebSocket Server | `SWOOLE_PROCESS` | `WS_PORT=9509`  | `config/autoload/server.php` |

- **进程模式**：`SWOOLE_PROCESS`，多 Worker 进程 + Task 进程
- **Worker 数量**：`swoole_cpu_num()`（动态适配 CPU 核数）
- **最大协程数**：100,000
- **HTTP/2**：已开启 `open_http2_protocol`

## 五、三大子系统关系

```
Synapse (IM 核心)
  ↕ Admin API + 共享 PostgreSQL
web-api (业务网关)
  ↕ HTTP REST
web-ht (管理后台前端) + C 端 App
```

- **Synapse** 负责：Matrix 协议、房间消息、登录鉴权、设备 Token
- **web-api** 负责：业务扩展数据、用户资料同步、圈子、笔记、VIP、账变推送
- **web-ht** 负责：运营管理 UI，通过 `/api/...` 调用 `web-api` 后台接口

## 六、关键设计原则

1. **不绕过 Synapse 直接改核心表**：用户密码、设备下线等必须走 Synapse Admin API
2. **ext\_ 前缀表为业务扩展**：`ext_users`、`ext_user_accounts`、`ext_circles` 等是本项目新增的扩展表
3. **Matrix MXID 以服务端配置为准**：`@username:im-sq01.bleiworc.xyz`，不信任客户端传入的 `home_server`
4. **资料变更同步多表**：昵称/头像更新后，`ProfileSyncService` 会同步到圈子、群、笔记等多张业务表
5. **账变通过 Redis Pub/Sub 推送**：`AccountChangeNotifyService → Redis → AccountPushHandler (WS)`
