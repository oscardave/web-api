# 06 · 核心模块与开发规范

## 一、分层架构规范

```
Controller（控制器）
  ↓ 参数校验 + 鉴权
Service（服务层，可选）
  ↓ 业务逻辑编排
Dao（数据访问对象）
  ↓ 数据库/缓存操作
Model（Eloquent ORM）
  ↓ 数据库表映射
```

### 各层职责

| 层 | 职责 | 规范 |
|----|------|------|
| **Controller** | 接收请求、参数校验、调用 Dao/Service、返回响应 | 不写业务逻辑，只做编排 |
| **Service** | 跨 Dao 的复杂业务逻辑（如 ProfileSyncService） | 无状态，可复用 |
| **Dao** | 封装数据库操作，返回 Model 或数组 | 不写 HTTP 逻辑 |
| **Model** | 表映射、关联关系、ModelCache 配置 | 继承 `App\Model\Model` |

## 二、控制器规范

### 2.1 注解路由

```php
#[Controller(prefix: 'api/v1/users')]
class UsersController extends AbstractController
{
    #[GetMapping(path: 'profile')]
    #[Middleware(CheckLogin::class)]
    public function profile(): ResponseInterface
    {
        // ...
    }
}
```

### 2.2 响应格式（BaseJsonTrait）

所有接口统一使用 `BaseJsonTrait` 返回 JSON：

```php
// 成功
return $this->success($data);
// 失败
return $this->fail($message, $code);
// 分页
return $this->paginate($paginator, $transformer);
```

响应结构：
```json
{
  "code": 0,
  "message": "success",
  "data": { ... }
}
```

### 2.3 参数获取

```php
// 推荐：使用 Hyperf 请求对象
$request->input('field', 'default');
$request->all();
$request->file('image');

// 鉴权：从 Bearer token 获取当前用户
$user = UsersCache::getUserByRequest($request);
// $user 为 ext_users 记录，$user->id 为 ext_user_id
```

## 三、Dao 层规范

### 3.1 命名约定

- 文件位置：`app/Http/Frontend/Dao/` 或 `app/Http/Backend/Dao/`
- 类名：`{Module}Dao`（如 `UsersDao`、`CirclesDao`）
- 方法命名：`get{Entity}By{Field}`、`set{Field}`、`create{Entity}`、`delete{Entity}`

### 3.2 查询构造器 vs ORM

```php
// 简单查询：使用 Model
$user = ExtUser::find($id);
$user = ExtUser::where('phone', $phone)->first();

// 复杂查询：使用 Db::table()
$list = Db::table('ext_users as u')
    ->leftJoin('ext_user_accounts as a', 'u.id', '=', 'a.user_id')
    ->select(['u.*', 'a.points'])
    ->where('u.status', 1)
    ->paginate(20);
```

### 3.3 事务使用

```php
Db::transaction(function () use ($data) {
    // 多表操作
    ExtUser::where('id', $id)->update(['nickname' => $data['nickname']]);
    ProfileSyncService::syncNickname($userId, $data['nickname']);
});
```

## 四、缓存层规范（`app/Caches/`）

### 4.1 ModelCache（自动缓存）

在 Model 中启用：
```php
use Hyperf\ModelCache\Cacheable;
use Hyperf\ModelCache\CacheableInterface;

class ExtUser extends Model implements CacheableInterface
{
    use Cacheable;
}
```

- Key 格式：`mc:default:m:{table}:{primary_key}:{value}`
- TTL：86400 秒（24h）
- 更新/删除时自动失效

### 4.2 手动 Redis 缓存（UsersCache）

```php
// 通过 access_token 获取用户
$user = UsersCache::getUserByToken($token);

// 通过 Request 获取当前用户（自动解析 Bearer token）
$user = UsersCache::getUserByRequest($request);
```

## 五、中间件规范

### 5.1 全局中间件（`config/autoload/middlewares.php`）

```php
'http' => [
    RouteLogMiddleware::class,   // 路由日志
    SessionMiddleware::class,    // Session
    ValidationMiddleware::class, // 参数校验
],
```

### 5.2 路由级中间件（注解）

```php
#[Middleware(CheckLogin::class)]      // C 端登录校验
#[Middleware(CheckAdminLogin::class)] // 后台登录校验
#[Middleware(CheckInternalAccess::class)] // 内部接口 IP 白名单
```

### 5.3 自定义中间件开发

```php
class MyMiddleware implements MiddlewareInterface
{
    public function process(ServerRequestInterface $request, RequestHandlerInterface $handler): ResponseInterface
    {
        // 前置处理
        $response = $handler->handle($request);
        // 后置处理
        return $response;
    }
}
```

## 六、Synapse Admin API 调用规范

所有需要修改 Synapse 核心数据的操作，必须通过 `HttpClient` 调用 Admin API：

```php
// 封装在 app/Common/HttpClient.php 或 app/Helpers/
$client = new SynapseAdminClient();

// 修改用户信息
$client->put("/_synapse/admin/v2/users/{$userId}", [
    'displayname' => $nickname,
]);

// 封禁用户
$client->put("/_synapse/admin/v1/deactivate/{$userId}", [
    'erase' => false,
]);

// 踢出设备（强制下线）
$client->delete("/_synapse/admin/v2/users/{$userId}/devices/{$deviceId}");
```

> **鉴权**：Admin API 需要 `Authorization: Bearer {admin_access_token}`，token 存储在环境变量中。

## 七、异常处理规范

```php
// 业务异常（返回给客户端）
throw new BusinessException(ErrorCode::USER_NOT_FOUND, '用户不存在');

// 系统异常（记录日志，返回通用错误）
throw new \RuntimeException('数据库连接失败');
```

全局异常处理器在 `app/Exception/Handler/` 中注册，统一格式化响应。

## 九、常见开发场景速查

### 场景 1：新增 C 端接口

1. 在 `app/Http/Frontend/Controllers/` 新建或修改 Controller
2. 使用 `#[Controller]` + `#[GetMapping]` / `#[PostMapping]` 注解
3. 在 `app/Http/Frontend/Dao/` 新建 Dao 方法
4. 如需鉴权，添加 `#[Middleware(CheckLogin::class)]`
5. 使用 `BaseJsonTrait` 返回统一格式

### 场景 2：新增后台接口

1. 在 `app/Http/Backend/Controllers/` 新建 Controller
2. 路由前缀使用 `/ht/v1/`
3. 添加 `#[Middleware(CheckAdminLogin::class)]`
4. 在 `app/Http/Backend/Dao/` 新建 Dao
5. 操作完成后写 `admin_logs` 日志

### 场景 3：新增定时任务

```php
#[Crontab(rule: '*/10 * * * *', name: 'MyTask', singleton: true)]
class MyTask
{
    public function execute(): void
    {
        // 任务逻辑
    }
}
```

### 场景 4：新增 Model

```bash
php bin/hyperf.php gen:model ext_my_table --pool=default
```

生成后在 Model 中添加 `use Cacheable` 启用缓存。

## 十、环境变量关键配置

| 变量 | 说明 |
|------|------|
| `APP_PORT` | HTTP 服务端口（默认 9005） |
| `WS_PORT` | WebSocket 端口（默认 9509） |
| `DB_HOST/PORT/DATABASE/USERNAME/PASSWORD` | PostgreSQL 连接 |
| `REDIS_HOST/PORT/AUTH` | Redis 连接 |
| `SYNAPSE_ADMIN_TOKEN` | Synapse Admin API Token |
| `SYNAPSE_BASE_URL` | Synapse 服务地址 |
| `DEFAULT_HOME_SERVER` | Matrix 默认 homeserver 域名 |
| `SMS_*` | 短信服务配置 |
| `MAIL_*` | 邮件服务配置 |
