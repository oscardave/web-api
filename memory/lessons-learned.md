## 架构经验

### lesson-001: 三域隔离的必要性
- **日期**: 2026-03-26
- **内容**: Backend/Frontend/Internal 三域严格隔离是正确的。共享逻辑通过 Service 层桥接，避免了跨域耦合。实践中容易犯的错误是为了"复用"直接引用其他域的 Dao。
- **来源**: 项目架构设计

### lesson-002: Synapse 共库的约束
- **日期**: 2026-03-26
- **内容**: 与 Synapse 共用 PostgreSQL 数据库意味着不能随意修改非 `ext_` 表。所有业务扩展必须通过 `ext_` 前缀表实现。迁移时需特别注意不影响 Synapse 核心表。
- **来源**: knowledge/04

### lesson-003: Swoole 与 FPM 的思维转换
- **日期**: 2026-03-26
- **内容**: Swoole 常驻内存模型要求开发者放弃 FPM 时代的"请求隔离"假设。静态属性、全局变量在协程间共享，会导致数据污染。Dao 的静态方法之所以安全，是因为每次调用只使用局部变量。
- **来源**: engineering-rules §10

## 流程经验

### lesson-004: 闸门脚本的价值
- **日期**: 2026-03-26
- **内容**: 三闸门（gatekeeper/plan/deliver）在 AI 辅助开发中价值巨大。入场闸门确保 Agent 了解项目上下文；规划闸门防止范围膨胀；交付闸门自动检查编码红线。不应跳过任何闸门。
- **来源**: 实践总结

### lesson-005: 知识文档需要与代码同步
- **日期**: 2026-03-26
- **内容**: knowledge/ 文档如果不随代码更新会逐渐过时，导致 AI 基于错误信息生成代码。ai-knowledge-sync.sh 的作用就是在交付时检测这种漂移。
- **来源**: 参考 web-project-web 实践
