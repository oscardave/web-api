# 登录注册与绑定手机/邮箱接口 - 前端对接文档

本文档描述 web-api（PHP）提供的 C 端登录、注册、验证码、重置密码及绑定手机/邮箱等接口，供前端对接使用。

**基础路径**：`/api/v1`

**认证方式**：登录、注册、发送验证码、检查是否已注册、重置密码等接口无需登录；绑定手机/绑定邮箱、获取用户资料等需已登录，请求时携带 `Authorization: Bearer <access_token>` 或项目约定的 Token 方式。

---

## 一、发送手机验证码（支持多国家）

**接口路径**：`POST /api/v1/index/phone-verify-code`

**用途**：注册、登录、重置密码、绑定手机等场景下，向指定手机号发送 6 位数字验证码。支持多国家/地区号码（E.164 格式）。

### 请求参数

| 参数         | 类型   | 必填 | 说明                                                                                                                                 |
|--------------|--------|------|--------------------------------------------------------------------------------------------------------------------------------------|
| phone        | string | 是   | 手机号。支持三种形式：① 中国 11 位（如 13800138000）；② 完整 E.164 数字串（如 8613800138000、14155551234）；③ 本地号，需同时传 country_code（如美国 4155551234 + country_code: "1"） |
| verify_type  | string | 否   | 验证类型，默认 `register`。可选：`register`、`login`、`reset_password`、`bind_account`（绑定手机时使用）                                |
| country_code | string | 否   | 国家/地区码（如 "86"、"1"、"44"）。传入时，phone 视为**本地号码**，后端会拼接为 E.164 再发短信；不传则按 phone 是否已含国家码或中国 11 位自动识别 |

### 请求示例

**中国（可不传 country_code，兼容旧版）**：
```json
{
  "phone": "13800138000",
  "verify_type": "register"
}
```

**中国（显式传国家码）**：
```json
{
  "phone": "13800138000",
  "country_code": "86",
  "verify_type": "register"
}
```

**美国（本地号 + 国家码）**：
```json
{
  "phone": "4155551234",
  "country_code": "1",
  "verify_type": "register"
}
```

**已带国家码的 E.164（可不传 country_code）**：
```json
{
  "phone": "14155551234",
  "verify_type": "register"
}
```

### 成功响应

```json
{
  "code": 0,
  "message": "验证码发送成功"
}
```

### 错误响应

```json
{
  "code": 非0,
  "message": "错误描述"
}
```

### 常见错误

| message                     | 说明                     |
|-----------------------------|--------------------------|
| 手机号不能为空              | 未传 phone               |
| 手机号格式不正确            | 无法识别为有效 E.164（如长度、国家码+本地号不合法） |
| 验证码发送过于频繁，请5分钟后再试 | 60 秒内重复请求          |

### 前端注意

- 验证码 5 分钟内有效
- 建议发送成功后启动 60 秒倒计时，防止重复点击
- 注册/登录/重置密码/绑定手机时，若使用「本地号 + country_code」方式，后续提交验证码、注册、重置、绑定时请保持同一套（同一 country_code 或同一 E.164 格式），否则验证码校验可能对不上

## 二、发送邮箱验证码

**接口路径**：`POST /api/v1/index/email-verify-code`

**用途**：注册、登录、重置密码、绑定邮箱等场景下，向指定邮箱发送 6 位数字验证码。

### 请求参数

| 参数         | 类型   | 必填 | 说明                                                         |
|--------------|--------|------|--------------------------------------------------------------|
| email        | string | 是   | 邮箱地址                                                     |
| verify_type  | string | 否   | 验证类型，默认 `register`。可选：`register`、`login`、`reset_password`、`bind_account`（绑定邮箱时使用） |

### 请求示例

```json
{
  "email": "user@example.com",
  "verify_type": "register"
}
```

### 成功响应

```json
{
  "code": 0,
  "message": "验证码发送成功"
}
```

### 常见错误

| message                     | 说明                     |
|-----------------------------|--------------------------|
| 邮箱地址不能为空            | 未传 email               |
| 邮箱地址格式不正确          | 邮箱格式非法             |
| 验证码发送过于频繁，请5分钟后再试 | 60 秒内重复请求          |

## 三、检查用户名或手机号是否已注册

**接口路径**：`POST /api/v1/register/check-available`

**用途**：注册页输入框实时校验。前端传入用户名称或手机号，后端根据格式自动判断并按「用户名」或「手机号」查询是否已注册。

### 请求参数

| 参数         | 类型   | 必填 | 说明                                                                 |
|--------------|--------|------|----------------------------------------------------------------------|
| keyword      | string | 是   | 用户名称（用户名）或手机号。后端自动判断：符合手机号格式（中国 11 位或 E.164 多国家）则按手机号查，否则按用户名（localpart）查 |
| home_server  | string | 否   | homeserver 域名，默认 `im-sq01.bleiworc.xyz`（与注册接口一致）       |

### 判断规则

- **手机号**：中国 11 位（1[3-9] 开头）、86+11 位、或其他合法 E.164（10–15 位数字），则按手机号在 `ext_users.bound_phone` 中查询是否已注册。
- **用户名**：其余情况视为用户名（localpart），转为小写后按 2–100 字符、仅允许 `a-z0-9._-` 校验格式，再在 `users` 表中查是否已存在。

### 请求示例

```json
{ "keyword": "alice" }
```

```json
{ "keyword": "13800138000" }
```

### 成功响应（未注册）

```json
{
  "code": 0,
  "message": "",
  "data": {
    "exists": false,
    "type": null
  }
}
```

### 成功响应（已注册）

| 字段   | 类型    | 说明                                                         |
|--------|---------|--------------------------------------------------------------|
| exists | boolean | 是否已注册                                                   |
| type   | string \| null | `username` 表示用户名已被使用，`phone` 表示手机号已注册；未注册时为 `null` |

```json
{
  "code": 0,
  "message": "",
  "data": { "exists": true, "type": "phone" }
}
```

### 前端建议

- 在注册页「用户名称」或「手机号」输入框失焦（blur）时调用；也可在点击「获取验证码」或「注册」前调用。
- 根据 `data.exists` 与 `data.type` 展示提示：`type === 'username'` 提示「用户名已被使用」，`type === 'phone'` 提示「该手机号已注册」。

## 四、用户注册

**接口路径**：`POST /api/v1/index/register`

**用途**：使用手机号或邮箱 + 验证码 + 密码 + **用户名**完成注册。注册前必须先调用发送验证码接口。注册成功后，**Matrix ID** 为 `@{username}:home_server`（用户名会转为小写存储），登录时可用该用户名或手机号/邮箱登录。

### 请求参数

| 参数        | 类型   | 必填 | 说明                                                                 |
|-------------|--------|------|----------------------------------------------------------------------|
| phone       | string | 二选一 | 手机号（与 email 二选一）；支持中国 11 位或 E.164，多国家时可传 country_code |
| email       | string | 二选一 | 邮箱（与 phone 二选一）                                              |
| country_code| string | 否   | 国家/地区码。手机号注册且 phone 为本地号时必传，与发验证码时一致       |
| username    | string | 是   | **用户名**，作为账号（Matrix ID 的 localpart）。2–100 字符，仅支持小写字母、数字、`.`、`_`、`-`；后端会转为小写存储，且全局唯一 |
| password    | string | 是   | 密码，6–32 位                                                         |
| verify_code | string | 是   | 6 位数字验证码                                                        |
| invite_code | string | 否   | **邀请码**，即邀请人的 `ext_users.id`（数字）。传则校验存在且有效，并写入邀请关系 |
| device_id   | string | 否   | 设备 ID，不传则自动生成                                               |
| device_name | string | 否   | 设备名称                                                              |

### 请求示例（手机号注册）

```json
{
  "phone": "13800138000",
  "username": "alice",
  "password": "MyPassword123",
  "verify_code": "123456",
  "device_name": "iPhone 15"
}
```

多国家示例（美国本地号 + 国家码）：

```json
{
  "phone": "4155551234",
  "country_code": "1",
  "username": "alice",
  "password": "MyPassword123",
  "verify_code": "123456"
}
```

### 成功响应

返回 Synapse 格式的登录信息，可直接用于后续请求：

```json
{
  "user_id": "@alice:im-sq01.bleiworc.xyz",
  "access_token": "syt_xxxxxxxxxxxx",
  "home_server": "im-sq01.bleiworc.xyz",
  "device_id": "XXXXXXXX"
}
```

### 常见错误

| message                     | 说明                     |
|-----------------------------|--------------------------|
| 请提供手机号或邮箱          | 未传 phone 或 email      |
| 请提供用户名                | 未传 username            |
| 用户名不能为空 / 用户名长度为 2-100 个字符 / 用户名仅支持小写字母… | 用户名格式或唯一性 |
| 验证码不能为空 / 验证码无效、已过期或已使用 | 验证码相关 |
| 该手机号已注册 / 该邮箱已注册 | 联系方式已被注册         |
| 邀请码无效                  | invite_code 对应 ext_users.id 不存在或无效 |

## 五、用户登录

**接口路径**：`POST /api/v1/login/login`

**用途**：使用账号 / 靓号 / 手机号 / 邮箱 + 密码登录。

### 请求参数

| 参数        | 类型   | 必填 | 说明                                      |
|-------------|--------|------|-------------------------------------------|
| identifier  | string | 是   | 账号、靓号、手机号或邮箱（任选其一）      |
| password    | string | 是   | 密码                                      |
| device_id   | string | 否   | 设备 ID，不传则自动生成                   |
| device_name | string | 否   | 设备名称                                  |

**identifier 支持格式**：账号（用户名或完整 Matrix ID）、靓号（纯数字）、手机号（支持中国 11 位及多国家 E.164）、邮箱。

### 请求示例

```json
{
  "identifier": "13800138000",
  "password": "MyPassword123",
  "device_name": "iPhone 15"
}
```

### 成功响应

```json
{
  "user_id": "@alice:im-sq01.bleiworc.xyz",
  "access_token": "syt_xxxxxxxxxxxx",
  "home_server": "im-sq01.bleiworc.xyz",
  "device_id": "XXXXXXXX"
}
```

### 前端注意

- 登录成功后，将 `access_token` 保存到本地（如 localStorage）
- 后续需认证的请求在 Header 中携带：`Authorization: Bearer {access_token}`

## 六、退出登录与退出所有设备

**退出当前设备**：`POST /api/v1/login/logout`  
**退出所有设备**：`POST /api/v1/login/logout-all`

请求头需携带 `Authorization: Bearer {access_token}`。成功响应为 `{}`。

## 七、忘记密码 / 重置密码

流程：**① 发送验证码**（手机或邮箱，`verify_type: "reset_password"`）→ **② 提交重置密码**。

### 7.1 发送重置密码验证码

复用「一、发送手机验证码」或「二、发送邮箱验证码」，将 `verify_type` 设为 `reset_password`。手机号支持多国家，可传 `country_code`。

**手机号示例**：
```json
POST /api/v1/index/phone-verify-code
{"phone": "13800138000", "verify_type": "reset_password"}
```

### 7.2 提交重置密码

**接口路径**：`POST /api/v1/index/reset-password`

**请求参数**

| 参数         | 类型   | 必填 | 说明                                      |
|--------------|--------|------|-------------------------------------------|
| phone        | string | 二选一 | 手机号（与 email 二选一）；多国家时可传 country_code |
| email        | string | 二选一 | 邮箱（与 phone 二选一）                   |
| country_code | string | 否   | 国家/地区码，手机号且为本地号时与发验证码一致 |
| verify_code  | string | 是   | 6 位数字验证码                            |
| new_password | string | 是   | 新密码，6–32 位                           |

### 请求示例（手机号）

```json
{
  "phone": "13800138000",
  "verify_code": "123456",
  "new_password": "NewPassword123"
}
```

### 成功响应

```json
{
  "code": 0,
  "message": "密码重置成功"
}
```

### 常见错误

| message                     | 说明                     |
|-----------------------------|--------------------------|
| 联系方式类型不能为空 / 联系方式不能为空 | 未传 phone 或 email      |
| 验证码无效、已过期或已使用  | 验证码错误或过期         |
| 用户不存在                  | 手机号/邮箱未注册        |

## 八、绑定手机号（支持多国家）

绑定流程：**① 发送验证码**（复用「一、发送手机验证码」，`verify_type: "bind_account"`）→ **② 提交绑定**。

### 8.1 发送绑定手机验证码

**接口路径**：`POST /api/v1/index/phone-verify-code`

与「一、发送手机验证码」相同，将 `verify_type` 设为 `bind_account`。手机号支持多国家，可传 `country_code`。

**请求示例**：
```json
{
  "phone": "13800138000",
  "verify_type": "bind_account"
}
```

多国家示例：
```json
{
  "phone": "4155551234",
  "country_code": "1",
  "verify_type": "bind_account"
}
```

### 8.2 提交绑定手机号

**接口路径**：`POST /api/v1/users/bind-phone`

**认证**：需登录，携带 Token。

**请求参数**

| 参数         | 类型   | 必填 | 说明                                                                 |
|--------------|--------|------|----------------------------------------------------------------------|
| phone        | string | 是   | 手机号。支持中国 11 位、完整 E.164、或本地号（此时需传 country_code） |
| verify_code  | string | 是   | 6 位数字验证码                                                       |
| country_code | string | 否   | 国家/地区码。phone 为本地号时传入，与发验证码时一致                   |

**请求示例**：
```json
{
  "phone": "13800138000",
  "verify_code": "123456"
}
```

**成功响应**：
```json
{
  "code": 0,
  "message": "绑定成功"
}
```

**常见错误**

| message                     | 说明                     |
|-----------------------------|--------------------------|
| 请先登录                    | 未携带或 Token 无效      |
| 手机号不能为空 / 手机号格式不正确 | 未传或格式非法           |
| 验证码无效、已过期或已使用  | 验证码错误或过期         |
| 该手机号已被其他用户绑定    | 手机号已被占用           |

### 8.3 绑定手机号流程

```
1. 用户输入手机号（多国家时选择国家并传 country_code）
2. 调用 发送手机验证码（verify_type: "bind_account"）
3. 用户输入收到的验证码
4. 调用 提交绑定手机号（POST /api/v1/users/bind-phone），多国家时同样传 country_code
5. 成功后可在用户资料中看到已绑定手机号
```

## 十、典型流程汇总

- **注册**：检查是否已注册（可选）→ 发送手机/邮箱验证码 → 用户填写验证码、密码、用户名等 → 用户注册
- **登录**：identifier + 密码 → 用户登录 → 保存 access_token
- **忘记密码**：发送手机/邮箱验证码（verify_type: reset_password）→ 提交重置密码
- **绑定手机**：发送手机验证码（verify_type: bind_account）→ 提交绑定手机号（需登录）
- **绑定邮箱**：发送邮箱验证码（verify_type: bind_account）→ 提交绑定邮箱（需登录）
